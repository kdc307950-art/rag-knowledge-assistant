> 文档版本：`0.1`
> 适用应用版本：`0.1.0`
> 最近核对：`2026-08-21`

本文定义现有功能的交付证据，不增加功能。`通过` 必须来自本次目标提交和目标环境的实际结果。

## 阻断验收项

### 静态和自动化验证

```powershell
uv sync --frozen --group dev
npx --yes pyright@1.1.311
uv run pytest tests -q

Set-Location frontend
npm ci
npm run lint
npm run test
npm run build
Set-Location ..

docker compose config --quiet
docker compose --profile monitoring config --quiet
docker compose build
```

任何失败都必须解释并重新验证；不能只报告最后一行或忽略 warning 的实际影响。

### 部署与安全

- [ ] 应用版本与目标提交已记录。
- [ ] 生产环境使用 `multi_user/users`，Cookie Secure 开启。
- [ ] `AUTH_SECRET`、模型 Key、metrics token、Grafana 密码、Webhook 相互独立。
- [ ] 证书由受信任 CA 签发，域名和有效期正确。
- [ ] HTTP 跳转 HTTPS，公网无法访问 live/ready/metrics。
- [ ] backend 单实例、单 worker，数据卷和备份卷已挂载。
- [ ] 至少一个 active admin，普通用户不能访问 admin 诊断。
- [ ] 企业微信实际收到 firing 和 recovery 测试消息。

### 主业务流程

- [ ] 用户登录、刷新恢复会话、退出后会话失效。
- [ ] viewer/editor/admin 权限符合 [ACL 契约](metadata-acl-contract.md)。
- [ ] 支持格式上传、任务轮询、完成后文档数变化。
- [ ] 空文件、超限、无权替换和队列繁忙返回明确错误。
- [ ] 已知问题检索到正确资料并展示来源。
- [ ] 无资料问题严格拒答，不自动使用模型通用知识。
- [ ] 用户主动通用回答带非知识库标识。
- [ ] 资料起草只使用当前可见资料。
- [ ] 删除和清空权限正确，更新期间写冲突 fail closed。

### 数据与恢复

- [ ] 创建离线备份成功并写入校验台账。
- [ ] 在隔离目录完成恢复演练。
- [ ] 恢复后向量库、manifest、用户库和文档数正常。
- [ ] 抽样问题在恢复数据上得到预期来源。
- [ ] 已记录实际恢复耗时；没有实测前不得声明 RTO。

### 可观测性

- [ ] live/ready 状态与故障注入结果一致。
- [ ] access/app/error 日志可通过请求 ID 关联。
- [ ] 日志抽查没有查询正文、文档正文或明文秘密。
- [ ] Prometheus 有采集数据，Grafana 面板可见。
- [ ] 告警和恢复通知链路完成实测。

### RAG 质量

- [ ] 黄金集由人工根据真实原始文档审核。
- [ ] `eval_retrieval.py` 结果记录 corpus 和治理配置指纹。
- [ ] Recall@1/3/5、MRR、拒答准确率、错误率和 busy rate 已保存。
- [ ] Groundedness 评审区分“引用存在”和“内容支持”。
- [ ] 业务负责人接受本轮质量结果或明确记录未达项。

## 当前已知限制

| 限制 | 影响 |
| --- | --- |
| 单机、单进程、单 worker | 不支持水平扩展、滚动多实例升级或多写者 |
| 会话和上传任务含进程内状态 | 重启后会话历史和任务快照丢失 |
| Chroma/HNSW 只支持离线备份契约 | 备份需要停写窗口 |
| 无多租户隔离 | 不能作为多租户 SaaS 安全边界 |
| 无 SSO/MFA | 用户身份只由本地用户库管理 |
| 用户管理 CLI 只支持创建 | 改密、停用、删除和角色变更没有正式运维入口 |
| LLM readiness 不发网络请求 | ready 不能证明供应商实时可用或余额充足 |
| SSE 取消是尽力而为 | 不能保证立即停止供应商推理或计费 |
| 引用校验不做自动事实蕴含证明 | 高风险回答仍需人工复核 |
| 外部检查与应用同机 | 不能检测整机断电、全网中断或监督任务自身停止 |
| 生产资源基线未建立 | 不能承诺 QPS、并发、P95、最大文档量或磁盘增长率 |
| RPO/RTO 未经目标环境演练 | 不能写入正式恢复承诺 |
| Compose 镜像默认标签为 `latest` | 发布必须额外保留不可变镜像标签才能可靠回滚 |

## 容量和性能证据要求

当前文档不虚构硬件推荐。投产前在目标语料、目标模型和目标主机上记录：

- CPU、内存、磁盘、模型缓存和网络；
- 文档数、总字节数、分块数和索引大小；
- 上传文件大小与解析/入库耗时；
- 并发用户数和请求模式；
- 首 token、总响应、检索和重排 P50/P95；
- 错误率、拒答率和供应商限流；
- 24 小时日志、缓存、质量库和向量库增长；
- 备份时长、备份大小、恢复时长和恢复结果。

只有这些数据被实际测量并由责任人确认后，才能形成资源规格、容量上限、SLO、RPO 和 RTO 承诺。
